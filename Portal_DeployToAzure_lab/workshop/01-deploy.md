# 01. 포털에서 리소스와 앱 배포

[이전](00-environment.md) · [목차](README.md) · [다음: 준비 완료](02-ready.md)

## 1. 배포 화면 열기

[Lab 홈의 Deploy to Azure 버튼](../README.md#배포-버튼)을 클릭하고 Azure 포털에 로그인합니다.
사용자 지정 배포의 **구독 범위** 화면인지 확인합니다. 하나의 기존 RG에 배포하는 방식이 아닙니다.
버튼이 404이거나 템플릿을 불러오지 못하면 중단합니다. 공개되지 않은 릴리스를 다른 버튼으로 우회하지 않습니다.

## 2. 매개변수 입력

| 입력 | 입력할 값 |
|---|---|
| 구독 | 환경 준비에서 확인한 승인 구독 |
| 배포 위치 | 배포 메타데이터 위치. 예: Korea Central. 실제 자원은 KRC/KRS에 생성 |
| prefix | 이 실습만의 새 값. 3~12자 소문자/숫자, 영문 시작. 예: `mydrws01` |
| expiry | 사용할 종료 날짜. 자동 삭제되지 않음 |
| allowedClientCidrs | 브라우저와 DR 터미널의 승인된 공인 IPv4 CIDR 배열 |
| administratorLogin | 새 환경의 PG 관리자 이름 |
| administratorPassword | 12자 이상 PG 정책을 만족하는 새 암호. 포털 보안 입력란에만 입력 |
| AKS/PG 크기·Kubernetes 버전 | 양 리전 제공·할당량·비용을 확인한 승인 값 |
| bootstrap·서비스·샘플·릴리스 값 | 템플릿의 고정 값 유지. 앱과 10 GB 샘플이 함께 배포됨 |

CIDR의 배열 형식은 `["203.0.113.10/32","198.51.100.20/32"]`처럼 입력합니다.
이 주소들은 문서용 예시이므로 실제 승인된 출구 주소로 바꿉니다. `0.0.0.0/0`는 사용하지 않습니다.
암호를 명령행·채팅·공개 parameters 파일에 옮기지 않습니다.

## 3. 만들기

1. **검토 + 만들기**를 선택합니다.
2. 비용·정책·권한 오류가 없고 새 prefix가 기존 환경과 충돌하지 않는지 확인합니다.
3. **만들기**를 한 번만 누릅니다. 인프라가 생성되고 Automation이 앱 자동 배포를 시작합니다.
4. 구독의 **배포** 화면에서 이번 배포의 정확한 **배포 이름**을 기록합니다. prefix와 같다고 가정하지 않습니다.
5. 배포가 `Succeeded`가 될 때까지 진행 상태를 확인합니다. 실패하면 해당 작업 오류를 먼저 확인합니다.

3개의 워크숍 RG와 2개의 AKS managed RG가 생성됩니다. 원본 앱 이미지를 사설 ACR로 가져와
양 리전 앱을 배포하므로 PC에서 Docker 빌드나 별도 앱 배포 명령을 실행하지 않습니다.

## 비용과 중단 기준

기존 full 환경의 알려진 소계 약 USD 1,615.41/월은 참고치이며 이번 환경의 새 견적이 아닙니다.
Automation·데이터·네트워크 사용량 등도 과금됩니다. 실패한 배포의 일부 자원도 남아 과금될 수 있습니다.
예산 알림은 이 템플릿에서 생성하지 않습니다. 보관 또는 삭제 시점까지 비용 책임을 정합니다.

## 완료 조건
