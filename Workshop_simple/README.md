# Azure DR workshop

**포털과 앱 버튼으로 확인하는 Korea Central(KRC) ↔ Korea South(KRS) DR 실습**입니다.
참가자는 브라우저로 진행하고, 전환 명령은 강사 또는 지정 오퍼레이터 한 명만 실행합니다.
개인 PC에 Docker나 Kubernetes 연결을 준비할 필요는 없습니다.

## 진행 순서

| 순서 | 실습 | 할 일 |
|---|---|---|
| 00 | [시작하기](00-start.md) | 구독·접속 IP·비용·담당자 확인 |
| 01 | [배포하기](01-deploy.md) | Deploy to Azure 클릭과 필수 값 입력 |
| 02 | [준비 확인](02-ready.md) | 포털 상태와 양쪽 앱 확인 |
| 03 | [앱 테스트](03-test.md) | 쓰기·읽기·샘플 버튼 클릭 |
| 04 | [전환과 원복](04-dr.md) | 짧은 명령과 앱의 리전 변화 관찰 |
| 05 | [정리하기](05-cleanup.md) | 정확한 대상 삭제와 잔여 과금 확인 |

각 문서의 완료 체크를 통과한 뒤 다음 단계로 이동합니다.
배포·복제에는 긴 대기가 있을 수 있어 **강사가 전날 준비하는 방식**을 권장합니다.
사전 준비된 환경이라면 01은 실제 배포 대신 배포 이력/입력값을 관찰하고,
누가 언제 배포했는지 기록하세요. 같은 환경을 다시 배포하지 않습니다.

## 꼭 알아둘 것

- **테스트 구독과 샘플 데이터만 사용**합니다. 앱은 HTTP이며 운영 데이터·운영 암호는 금지합니다.
- 포털에는 owner/budget 입력이 없고 예산·owner 태그·이메일 알림도 만들지 않습니다.
  그렇다고 무료이거나 과금이 차단되는 것은 아닙니다. expiry도 자동 삭제가 아닙니다.
- 업무 PaaS와 ACR은 private을 유지합니다. 승인된 public 예외는 bootstrap Automation 계정 하나입니다.
- **포털 배포 성공 ≠ 앱 준비 완료 ≠ 샘플 복제 완료**입니다.
- 이 과정은 planned 전환 기능 실습입니다. 리전 전체 장애·성능·SLA·RTO/RPO 인증이 아닙니다.
