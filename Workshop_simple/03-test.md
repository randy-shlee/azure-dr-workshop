# 03. 앱 버튼과 10 GB 샘플 테스트

[이전](02-ready.md) · [목차](README.md) · [다음: DR](04-dr.md)

## 목표

서비스 생존 표시뿐 아니라 실제 데이터 작업과 **첫 전환 전 복제**를 확인합니다.
동일 UUID를 비교하는 동안 다른 사용자가 동시에 쓰기 버튼을 누르지 않습니다.

## 할 일

1. TM 탭에서 **지금 새로고침**, **10초 자동 새로고침**을 켜고 서비스 카드를 확인합니다.
2. **쓰기 테스트 → 읽기 테스트**를 한 번 실행해 UUID·UTC·각 서비스 결과를 기록합니다.
3. **샘플 데이터 확인**을 누릅니다. 정상 자동 배포는 이미 샘플을 올렸으므로
   다시 업로드할 필요는 없습니다.
4. 업로드 기능도 체험한다면 **샘플 데이터 업로드 / 재개**를 누르고 확인 창을 승인합니다.
   동일 layout의 올바른 기존 파일은 재사용합니다. 서버 생성 기능이며 PC 파일 선택이 아닙니다.
5. `completed` 후 샘플을 다시 조회하고, **새 manifest 종료 fence**까지 복제가 완료될 때까지 기다립니다.
   업로드 완료와 복제 완료는 별도입니다.

| 결과 | 판정 |
|---|---|
| PG/Redis/Blob/Search 작업 | 활성 서비스의 실제 성공. partial/error는 전체 성공 아님 |
| EH 읽기 | sequence metadata이며 본문 소비/재생 증거는 아님 |
| Search count | 비동기 반영 가능. 양 지역 인덱스가 복제된다는 뜻 아님 |
| 기본 샘플 | large 8개(1 GiB 7개 + 386,655,232 bytes), small 2,000개 |
| 총 payload | **2,008개 / 정확히 10,000,000,000 bytes**. UI의 약 9.313 GiB도 같은 값 |
| 복제 | 양 endpoint 전체 파일/크기 일치, 실제 1 MiB 읽기 성공, Last Sync Time ≥ manifest 종료 |

확인 대상은 데이터 파일입니다. manifest/control JSON을 2,008개 payload에 더하지 않습니다.
업로드 상한은 **decimal 10 GB**이며 입력/요청으로 올릴 수 없습니다.
동시 시작은 공유 lease로 제한되고 HTTP 409이면 진행 상태를 관찰합니다.
기존 다른 manifest/잘못된 크기의 데이터는 삭제하지 말고 강사에게 전달합니다.

샘플 목록은 **300초 캐시**입니다. 10초 화면 갱신이 샘플 목록을 계속 조회하지는 않습니다.
업로드/재개 직후에는 최대 5분 뒤 샘플 버튼을 다시 누르세요.
한 앱에서 먼저 완료되어도 다른 앱의 오래된 캐시를 새 검증 결과로 제출하지 않습니다.

## DR 의미

양 앱 일반 Blob 작업은 같은 계정의 **primary hostname**, PG는 writer alias를 사용합니다.
Storage `-secondary` 읽기는 이 단계의 복제 probe일 뿐 KRS 앱의 일반 DR 읽기 경로가 아닙니다.
EH는 metadata-only, Redis는 active geo, Search는 독립 인덱스라는 차이를 설명합니다.

## 안 되면 멈추기

오류 해결 없이 쓰기/업로드를 반복하지 않습니다. 쓰기는 분산 트랜잭션이 아니며
부분 성공과 EH 재시도 중복이 있을 수 있습니다.
`null`/pending/불일치/보조 읽기 실패면 **DR 진행 보류**입니다.
과거 10 GiB 예산 데이터는 새 10 GB 테스트와 별도로 보존합니다.

## 완료 체크

- [ ] 양 샘플 inventory·실제 읽기·Last Sync Time fence 확인
- [ ] 업로드/재개를 했다면 갱신된 manifest 기준으로 다시 복제 확인
