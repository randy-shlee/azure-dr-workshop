# 04. 승인된 DR 전환과 원복

[이전](03-test.md) · [목차](README.md) · [다음: 정리](05-cleanup.md)

## 목표와 실행 경계

Storage 계정 planned failover/failback, PostgreSQL planned switchover,
EH metadata fail-forward와 TM 응답 리전을 관찰합니다.
**배포/평시 검증은 성공했으나 실제 전환·원복은 아직 실증하지 않았습니다.**
아래는 별도 승인 후 수행하는 실습 절차이며 성공 보장이 아닙니다.

명령은 [강사용 환경 준비](instructor.md#2-오퍼레이터-터미널-한-번-준비)를 마친
오퍼레이터 한 명만 실행합니다. 참가자는 TM 브라우저 탭을 유지하고 UTC를 기록합니다.
앱에 DR 실행 버튼은 없으며 참가자가 TM 포털을 임의 변경하지 않습니다.

## 할 일

### 1. 첫 전환 전

양 앱/서비스/샘플 게이트, Storage Live·Planned 지원, PG KRC writer/KRS replica,
EH KRC synchronized pairing, TM 양 Online을 강사가 확인합니다.

```bash
bash scripts/drill/00-precheck.sh
```

실패하면 진행하지 않습니다. 이 스크립트는 **첫 drill baseline**이며
샘플 exact byte/읽기와 앱의 모든 데이터 의미를 대신 검사하지 않습니다.

### 2. KRS 전환

```bash
unset CONFIRM
bash scripts/drill/10-failover.sh
```

`FAILOVER <prefix>`를 확인하고 승인합니다. 실제 순서는 다음과 같습니다.

**Storage Planned 완료 → EH alias KRS → PG KRS switchover → TM KRC Disable → DNS/데이터 확인**

Storage 작업이 수 시간 걸릴 수 있습니다. 같은 명령을 중복 실행하지 않습니다.
두 배지 KRS/KRS, Storage 실제 primary KRS, PG writer KRS, EH KRS active를 확인합니다.
**쓰기 → 읽기**로 Blob/PG 동일 UUID와 EH send를 확인하고 Redis/Search 실제 결과도 별도로 봅니다.
이때 `-secondary` 샘플 버튼/평시 smoke를 전환 성공 판정에 재사용하지 않습니다.

### 3. 앱 KRC 원복

```bash
unset CONFIRM
bash scripts/drill/20-failback.sh
bash scripts/drill/99-restore.sh
bash scripts/eh-georecovery.sh status
```

`FAILBACK <prefix>` 승인 후 **Storage KRC → PG KRC → EH active 확인 → TM KRC** 순서입니다.
두 배지 KRC/KRC, Blob/PG 동일 ID 읽기/쓰기, Redis/Search와 EH 접근을 재확인합니다.
TM 양 endpoint는 Enabled/Online이어야 합니다.

## 반드시 남는 차이

| 항목 | KRC 앱 원복 후 |
|---|---|
| Storage / PG / 사용자 응답 | KRC 복귀 |
| EH alias | **KRS 유지**. 이전 KRC namespace로 자동 failback하지 않음 |
| EH 이전 이벤트 | KRC에 남음. 자동 복제/replay/offset 이식 없음 |
| 다음 EH 보호 | 새 EMPTY namespace·별도 승인 필요. 기존 이벤트/namespace 삭제 금지 |

EH가 KRS에 남으므로 `00-precheck.sh`/`wait krc`를 다시 통과시키려 되돌리지 않습니다.
사후 역할/데이터 확인은 [고급 Lab 06](../workshop/labs/06-drill.md)을 따릅니다.
`99-restore.sh`는 프로브/TTL만 복구하며 데이터 역할 원복 명령이 아닙니다.
기본은 fast 설정을 사용하지 않습니다.

## 안 되면 멈추기

부분 실패 시 CSV `ERROR`, 실제 Storage/PG/EH 역할과 TM 상태부터 확인합니다.
무작정 반대 명령/인프라 재배포/unplanned 승격을 실행하지 않습니다.
KRC endpoint만 끄는 **DNS 경로 체험은 전체 DR가 아닙니다**.
실제 장애 주입·RTO/RPO 인증·99:1은 이 과정 범위가 아닙니다.
