# 04. 전환과 원복

[이전](03-test.md) · [목차](README.md) · [다음: 정리하기](05-cleanup.md)

## 목표

planned backend 전환과 사용자 응답 리전을 관찰하고 안전하게 KRC로 원복합니다.
**리전 전체 장애나 Storage 계정 failover는 실행하지 않습니다.**

## 할 일

명령은 [강사용 준비](instructor.md#2-오퍼레이터-터미널-한-번-준비)를 마친
**지정 오퍼레이터 한 명**이 저장소 루트의 Bash에서 실행합니다.
참가자는 TM 앱 탭에서 관찰합니다. 새 터미널에서 곧바로 실행 가능한 무설정 명령이 아닙니다.

1. 전환 전 게이트를 확인합니다. 샘플 완료와 PG/EH 현재 역할도 강사가 확인합니다.

```bash
bash scripts/drill/00-precheck.sh
```

2. KRS planned 전환을 실행하고 출력된 `FAILOVER 팀prefix` 확인 문구를 입력합니다.

```bash
bash scripts/drill/10-failover.sh
```

3. 앱에서 두 배지가 **KRS/KRS**, Storage 읽기가 secondary인지 확인합니다.
   **쓰기 테스트 → 읽기 테스트 → 샘플 데이터 확인**으로 실제 결과와 UTC를 기록합니다.
   강사는 PG/EH 실제 역할을 확인합니다. 배지만으로 backend 역할을 판단하지 않습니다.
4. 오퍼레이터가 원복을 실행하고 `FAILBACK 팀prefix`를 확인합니다.

```bash
bash scripts/drill/20-failback.sh
bash scripts/drill/00-precheck.sh
```

5. 앱의 두 배지 **KRC/KRC**, 쓰기/읽기 성공을 다시 확인합니다.
   포털 Traffic Manager Endpoints도 양쪽 Enabled/Online인지 확인합니다.

## 정상 상태

| 시점 | 응답 리전 / TM 안내 | 실제 전환 순서 |
|---|---|---|
| 평시 | KRC / KRC | 양 endpoint Enabled, KRC 우선 |
| 전환 | KRS / KRS | EH geo 사용 시 KRS 승격 → PG KRS → TM KRC Disable |
| 원복 | KRC / KRC | PG/EH를 먼저 KRC로 복귀 → KRC endpoint Enable |

**lite는 EH를 제외**합니다. Storage 쓰기 primary는 KRC에 남고 KRS 앱은 secondary 기본 읽기입니다.
DNS/기존 연결 때문에 배지가 늦게 바뀔 수 있습니다. 먼저 UTC를 기록하고 필요하면 시크릿 창으로 확인합니다.
빠른 프로브/TTL 0 설정은 이 기본 과정에서 사용하지 않습니다.

## 안 되면 멈추기

오류/부분 성공 시 반대 명령을 바로 실행하거나 Bicep을 재배포하지 않습니다.
강사가 로그·PG/EH 역할·TM 상태를 확인합니다. KRC endpoint Disabled 중에는
평시 precheck의 양쪽 Enabled/Online 게이트가 실패할 수 있으므로 중간에 반복하지 않습니다.

선택 체험으로 포털에서 KRC endpoint만 Disable/Enable할 수는 있지만 **트래픽 경로만 변경**합니다.
이것을 PG/EH까지 전환한 전체 DR 성공으로 기록하지 말고, 본 전환 순서와 섞지 않습니다.

## 완료 체크

- [ ] KRS 전환, 실제 데이터 작업과 UTC 기록
- [ ] backend·두 배지 KRC 복귀, 쓰기/읽기 재확인
- [ ] TM 양 endpoint Enabled/Online, 기본 프로브/TTL 상태 확인
